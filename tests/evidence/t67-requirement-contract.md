# T67 · 六关键词与同版需求持久保存红合同

依据：已批准C2F、spec K3。T66绿回执6f38c76a72已核实。本轮先考题，不改实现。

## 用户交付与检查

1. 场景下一页有6项带提示/例子的短输入：地点、我的角色、对方角色、话题、沟通目标、特别情况；都可留空。五种帮助语言均可填写和保存，不要求英语作文。
2. 显式“保存需求”把原描述、六字段和当前帮助语言作为一个快照保存。保存后刷新可恢复，返回修改不丢关键词；未保存的输入不假称已保存。当前只是需求保存，不显示生成成功，不创建任务或调用模型。
3. 服务端以验证后的会话确定归属。本地新需求库沿用既有Node SQLite事务模式，独立于旧生成/课程库；不是云端，也不迁移旧库。以跨实例、独立子进程及真实HTTP处理器验证持久保存。
4. 每账号一个当前工作需求，历史版本保留。初始expectedRevision为0；内容变化产生下一版本，同内容重试复用当前版本；不同内容的过期版本冲突不能覆盖当前记录。并行不同修改只允许一个获胜，另一个明确冲突。
5. 读取失败不以空需求冒充成功；保存失败保留输入并可重试。冲突先保留用户输入，只有用户主动载入已保存版本才替换；不能自动重试覆盖他人修改。换号/过期和迟到响应不混入别人的草稿。

## 内部接线合同

内容结构：`{description, language, keywords:{location,learnerRole,partnerRole,topic,goal,special}}`。描述1–2000 UTF-16字符且不能全空白，原文保留；每关键词0–200字符，缺省规范为六个空字符串；language仅现有五种。未知内容字段、数组、非字符串拒绝。

模块`lib/scene-requirements.ts`导出`createSceneRequirementStore({directory,sessionSecret})`：`get({cookie,now,revision?})`返回本人指定/最新版本或null；`save({cookie,now,expectedRevision,content})`返回`{revision,content}`。身份来自cookie，不接受owner作为授权。

HTTP `/api/scene-requirements`：GET最新或`?revision=N`；PUT body为`{expectedRevision,content}`，返回`{requirement}`。空库GET为`{requirement:null}`。PUT要求同源Origin，流式体上限12000字节；未知body字段拒绝。401身份失效、400输入无效、409版本冲突、403来源错误、413过大、503本地配置/临时故障；私有响应no-store且不泄漏owner/cookie/路径。configured路由只用本地目录，Vercel拒绝假持久化。

旧T65/T66根路径测试只补新GET接口的空记录替身，保留全部既有断言与会话替身；真实身份/存储/隔离由新增domain/HTTP测试验证。浏览器替身不是后端持久性证明。
