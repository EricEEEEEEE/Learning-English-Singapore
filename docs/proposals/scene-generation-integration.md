# T61：自述场景到真实课程的接入方案

2026-09-25。T60绿档6ed1da5400、557项验证通过。本轮公开资料核查与方案准备，不读取密钥、不生成、不充值、不发布。

## 交付路径

用户描述（母语）→确认对象/目的/起点→语言模型产出结构化脚本→审核及计价→按角色生成语音→按实际音轨时长分段→LTX异步生成→媒体下载与校验→拼接/字幕与词句绑定→正式课程进入已实现四页→后续接第五步与账户库。

例如“孩子同学生日party，我想与其他家长聊天”：脚本需覆盖到场打招呼、确认孩子关系、简短聊活动、告别，不得套为家长会。集体家长会与一对一会谈分别处理角色、公开说明与私人反馈。禁止把未经确认的学校规则、孩子姓名、成绩或过敏事实写成已知；必要信息用少量选项澄清。用户文本是场景数据，不得覆盖服务端预算或系统指令。

## 当前代码差距

lib/scene-course.ts只接受已有完整媒体、台词时间、五语释义和回合。它是发布给播放器前的校验器，不是生成器。app/api目前只有登录和临时私有演示接口，没有生成任务路由。原LTX样片由本地临时实验脚本产生，不能直接当持久生产后台。

需先建立“生成中的草稿”和“可学习课程”的边界：脚本阶段未有真实时间，不填假时间；TTS完成后用实测时长定位字幕；媒体全部通过后才转为T60课程结构。媒体失败不得显示课程已完成。

## 分工及实际限制

- 语言模型：通过OpenAI结构化输出生成roles、scenes、lines、phrase source IDs、translations、镜头指令；结构符合schema不等于事实或教学质量正确，另做源台词、语义和角色审核。具体文本模型与价格在首个真实请求前固定，不凭名称猜最优。
- OpenAI语音：每个角色独立生成，保留原音和对应line ID。原TTS-1只证明视觉探针，不能替代新加坡口音审查；指令控制口音的TTS主路线仍需听审和预算依据。
- LTX：当前已验证路线ltx-2-5-fast、720×1280、24fps，audio-to-video异步接口。先准备音轨，显式传模型/分辨率，不能依赖默认参数。官方单段最长20秒；先按12–20秒自然语义边界规划，实际音轨超限再分段，不裁掉单词。首尾参考帧帮助连贯，但不能保证跨段人物、嘴型和场景无漂移。
- 合成：从自有生成资产构建可复用镜头、双方音轨及回合片段，完整视频供第一步，角色片段供第四/第五步。不能直接用完整MP4代替自由互动。
- 存储：长任务须由持久队列/worker执行，不依赖网页停留或一次Web请求。Vercel现有Web层可收请求/查状态，外部worker和私有持久存储部署待单独落实，不擅自上生产。

## 状态与重复收费防护

拟状态：draft → awaiting_budget → queued → script_ready → audio_ready → video_pending → assembling → validating → ready；另有failed、cancelled、submission_unknown。

任务身份绑定accountId、courseId、revision和inputHash。每阶段记录资产校验值、实际时长、供应商job ID、尝试次数和预留金额。相同已成功阶段复用资产；用户主动改变需求建立新版本。

提交前持久化意图和预算预留，拿到供应商job ID后落盘，再查询同一job。POST超时但没有job ID时标submission_unknown：本地去重不能证明供应商未接单，不自动重提或释放预算。仅明确失败且费用核清后才允许批准的新尝试。取消只停止后续阶段，不能保证已提交请求退款或停止计费。

任务查询及资产下载按用户归属鉴权；不能相信浏览器传来的账户身份。密钥与签名下载地址只在服务端；下载到自有持久存储后提供私有访问。重复点击、刷新、断线恢复、并发、余额不足均不能新建隐形付费任务。
