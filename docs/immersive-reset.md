# 场景优先重整：产品与实施决策稿

2026-09-23。依据用户本轮视频及纠偏要求；这是文档修订，不是新开发、发布或费用授权。

## 1. 核心结论

产品应是“进入一个生活场景，先看懂听懂，再成为其中一个参与者”的学习体验。场景真实性来自空间、人物关系、任务、物品、动作、语音与回应的连续性；不要求照片级人物，不要求VR或用户摄像头。

旧规格已有视频与主动对话要求，问题不只是漏写功能：§8.2把完整场景镜头降为按需加入，执行又连续扩大离线替身，导致主体验始终没有被证实。测试通过只能说明局部实现符合考题，不能替代用户对“像身处现场”的判断。本次B2U不能记为产品方向验收通过；历史技术绿档仍有效。

## 3. 用户体验主线

用户用母语说“我要去哪里、跟谁、办什么、最担心什么”→选择匹配场景或申请生成→直接看到有声音的情境→自由重听短段→点击“换我来”→对方在相同情境下朝用户先开口→用户说、求助或继续听→练一个合理变化。

第一视角：镜头处于学习者的位置，对方的目光、声音和动作面向该位置。示范仍有两方交流，但学习者一方可以画外音，不强制两个可见卡通头像。外部素材可以有不同视角，必须说明，不能把非第一视角片伪称为第一视角。

屏幕以场景视频为主体；“重听这一句／慢一点／换我来／帮我一下”为主要操作。完整台词默认收起；英语字幕可选，关键母语提示可唤出。零基础可先开母语辅助，逐步减少，不强迫靠读字理解。设置和测试按钮不进入学习主流程。

引导问答仍保留，但先看一段体验可跳过登录与完整问答。账号用于保存、权限和后续个人化，不成为第一次看场景的门槛。微信保留计划，Google-first沿用已有决定。

## 4. 两条内容来源，三种明确状态

| 路线 | 能交付什么 | 必须避免的误称 |
| --- | --- | --- |
| 优先：按需求生成 | 模型规划镜头/对白，生成可重复播放的场景片；随后AI扮演场景角色 | 预制片不能标“刚为你生成”；任务提交不算已有视频 |
| 可接受：精选网络场景 | 返回匹配的原作者链接；平台允许时官方播放器嵌入 | 链接不能保证可剪辑、配音、下载、训练、变速或精确逐句重播 |
| 后续：第一视角实时参与 | 场景人物听到用户发言后真实回应，保持场景目的与角色连续性 | 一个能播放的视频或会动的头像不等于沉浸式开放对话 |

每个入口标“原作者视频／AI生成示范／AI情境对练”。网络原视频转入练习时明确“下面是基于该情境的AI模拟”，不暗示原博主正在回应。未经许可不复用原人物肖像声音；采用独立虚构角色。原片的本地口音和内容与AI练习声音分别标来源。

AI主动说话、OpenAI负责AI语音、听优先说其次、所有新来者及近零基础群体、新加坡本地语境和口音尊重，全部保留。原作者视频保留其原始声音，属于明确的内容来源例外，不用OpenAI重配原片并冒称原声。

## 5. 技术拆解与核查结论

本次只核查官方公开文档，未运行媒体模型，未做速度排名。

- 固定示范：候选LTX的音频到视频接口，可提交音轨并异步取回视频。短镜头组合为短课需另验角色、场景和声画连续性。多分钟完整课不能从单段接口能力直接推定。[LTX音频到视频](https://docs.ltx.io/api-documentation/api-reference/async-video-generation/submit-audio-to-video)
- 实时角色：Runway官方LiveKit集成接受代理已生成的音频并输出角色视频，允许独立选语音层；因此保留OpenAI语音有接入依据。但复杂物品操作、空间持续变化及完整第一视角场景仍要实测，不从avatar能力推导已解决。[Runway集成](https://docs.dev.runwayml.com/characters/livekit/)
- 播放与实时传输：官方LiveKit提供avatar视频轨接入方式。传输工具成熟不代表本项目媒体链已跑通。[LiveKit](https://docs.livekit.io/agents/models/avatar/)
- 网络内容：YouTube官方IFrame API提供嵌入和播放控制。嵌入是否允许、可用速度和地区可访问性逐片核查；不保证所有平台提供同等能力。[播放器文档](https://developers.google.com/youtube/iframe_api_reference)

上述依据支持候选路线，不证明精确组合质量、最低成本、最快时延或学习效果。模型和价格在真实试验前再次核对。

### 两条媒体管线不能混为一条

示范：场景意图→短剧分镜→经校验的双角色对白与OpenAI音轨→镜头生成/剪接→整段媒体检查→固定版本播放器。

参与：同一情境事实与角色设定→用户音频→OpenAI实时回应→音频驱动角色视频与场景状态→同步播放。用户新意图改变场景状态，不能每说一句都等待整段短剧重新生成。

实时场景若只能保持一个静态背景中的人物近景，必须把能力如实列出，交用户判断是否足够；不能自行判为沉浸体验已通过。照片级画质不是优先门槛，能看见语义相关动作才是。

### 场景数据新增字段（设计合同，尚未实现）

来源类型、原始URL/作者/平台、访问检查时间、嵌入/改编许可证据；场景目标与未知事实；地点/角色/学习者视角；镜头与语义动作；对白/音轨/视频版本；句级时间点及人工核对状态；辅助语言；可用播放器能力；是否具备AI对练；本地表达审查状态。

仅“已获授权自托管且有可靠时间轴”的媒体承诺精确逐句/A-B；外链能力不足就显示限制。不得为凑功能而生成无依据的时间点或全文字幕。

## 6. 第一条完整体验的样片计划

酒店前台用于对齐参考风格，不把旅行当整个产品定位。设计一个虚构前台、住客第一视角，短段覆盖问候、确认预订、一个追问、一个自然收尾。人名、日期、价格均合成且明确为练习，不能表示真实酒店政策。

这是建议的60–90秒视觉体验片，不是限制最终课程长度；先做15–30秒关键片段让用户判断方向，再扩完整片。还要补一个新加坡生活样例（如熟食中心点餐）以核对可迁移的风格，避免只对酒店做专用展示。

同一场景对练至少检查：用户沉默、说没听懂、问另一个合理问题、中途打断、改变需求；对方先说。没有真实音视频就不能进入这个验收。生成失败可选原作者场景或取消，不回退成文字卡片后宣称成功。

等待时间分开记录：现有素材可播放、生成任务排队、第一段合格视频、完整示范、用户说完到实际可听回应。旧P95目标作为待验证目标保留，不做已实现承诺。新视频不能即时产出时明确等待，不用无关缓存伪装即时生成。

## 7. 新门槛与停止条件

先回答“用户看见的是不是想要的场景”，再回答“是否能反复听”，再回答“能否参与”，最后扩展账号和记录。用户尚未认可样片就不继续扩充外围功能。

1. 来源门：链接有效、来源清楚、允许的使用方式明确；未授权原片不上传到生成商。
2. 体验门：视频有真实可听内容、场景空间与动作；用户明确认可方向。内部自动测试不能代替此项。
3. 听力门：音轨清楚、字幕可关闭、帮助可得、支持能力范围内的重播；只有合成练习不代表能力评级。
4. 对练门：实际语音与画面，第一视角先开场，接住新问题与沉默帮助；有可检查录制和延迟日志。
5. 上线门：数据与费用边界、设备、审查、保存删除等原有要求仍有效。
